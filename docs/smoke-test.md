# 发布前冒烟测试清单

每次发版前由一个人从头到尾走一遍，**每条都要能观察到明确结果**。任一条不通过即阻断发布。

- 适用版本：0.4.12 及以后
- 预计耗时：25–35 分钟（Electron 桌面端）/ 15 分钟（Web 端可跳过标 🖥 的项）
- 前置：准备好 2 个歌单（一个 30 首以上、一个 3 首以内）、1 张 VIP 专辑、1 首无版权歌曲

自动化部分先跑：

```bash
npm run lint && npm run test:unit
```

两条都必须是 0 错误。`npm run test:unit` 的期望输出结尾是
`27 passed, 0 failed, 0 skipped`。它只覆盖纯函数（歌词解析、时间/字节格式化、
缓存 URL 白名单、默认设置、律动映射与节拍检测），**界面行为必须靠下面的人工清单**。

## 本轮新增 / 高风险区域

优化改动集中在这六处，回归时优先重点走：

### 1. 歌词背景律动

- 频谱来源必须只挂在 `masterGain` 上做旁路，**不能**再接 `destination`（否则双声道叠加，听感变成回声）。
- 取不到频谱（跨域音源、解码失败、AudioContext 被挂起）时必须降级成静止背景，而不是显示随机抖动。
- 关掉律动后 rAF 循环要真的停掉，不能留一个空转的每帧回调。
- 相关用例：`tests/audio-analyser.test.js`（`mapFrameToVars` / 节拍检测 / 配置归一化）。

### 2. 无缝播放（crossfade）

- `crossfadeDuration = 0` 时必须是瞬时切换，不能有可听见的静音间隙。
- 设为 800ms 时，两首歌之间应能听到明显的交叉淡入淡出，且总时长不出现叠加。
- 连续快速点「下一首」10 次：不能出现两首歌同时出声、不能内存持续增长。
- 播完最后一首自动停止，不能无限循环淡入淡出。

### 3. 继续收听

- 历史保留最近 8 条；同一首歌重复播放只保留最新一条，不刷屏。
- 卡片显示的进度必须与真实播放位置一致（拖到 1:30 后退出，重开应停在 1:30 附近而不是 0:00）。
- 「清除」后重启不应复活。

### 4. 命令面板

- `Ctrl/Cmd+K` 打开，`Esc` 关闭；焦点自动落在输入框。
- 输入「播放」应能匹配到「播放/暂停」动作；↑↓ 切换高亮项，回车执行，执行后自动关闭。
- 空输入时显示「动作 / 导航 / 搜索」三组；有输入时只保留匹配组。
- 在设置页、歌词页按快捷键同样能打开（不被页面自身的键盘监听吞掉）。

### 5. 音频设备热插拔

- 插入/拔出耳机后，设置页的输出设备下拉列表自动更新，不需要重启。
- 正在播放时拔出当前输出设备：声音切回默认设备或静音，**不能崩溃、不能变成无声且无法恢复**。
- 设备被移除后设置里不应保留一个已不存在的 `deviceId`。

### 6. 设置页分组导航

- 七个分组锚点必须与右侧区块一一对应，点第 7 个能滚到「集成」。
- 滚动到底部时高亮必须停在最后一个分组，不能卡在第 5 个。
- 深色模式下左侧导航的选中态对比度足够（≥ 4.5:1）。

## 已知的构建环境限制

- **不要在这个仓库上跑 `npm install` / `yarn add`**：`node_modules` 曾被 Windows 的 safe-delete shim 破坏，是逐文件恢复回来的。任何安装都可能让当前可用的构建失效。
- 因此**没有 Vitest/Jest**。单元测试跑在 `tests/run.js` 上——它用已经在 `dependencies` 里的 `esbuild` 把 `tests/index.js` 打成一个 CJS 包，然后在同一个 Node 进程里 `require` 它。
- 想加用例：在 `tests/` 下新建 `*.test.js`，用 `tests/harness.js` 的 `describe` / `it` / `assert`，再到 `tests/index.js` 里 `import` 一次即可。
- `tests/run.js` 的解析规则：`@/foo` → `src/foo`；`howler` / `dexie` / `axios` / `vuex` / `@/store` / `@/api/**` 等浏览器或 Electron 专用模块被替换成 `tests/stubs/empty.js` 里的惰性 Proxy。想测新的纯函数模块，先确认它没有在导入期触碰 DOM 或 Vuex。
